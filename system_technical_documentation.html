1. System Architecture

The platform separates heavy mathematical vector preprocessing from fast real-time serving pipelines. This ensures sub-100ms response times by loading indices into memory and lazily writing user profile updates to storage.

2. AI Model & Indexing

Rather than building or training a custom machine learning model from scratch, we leverage a pre-trained language model that already maps English sentences to rich semantic representations. We couple this with a vector search engine to find matches.

Sentence Transformers

We use Hugging Face's all-MiniLM-L6-v2. It takes descriptions of what happens in video clips and encodes them into a 384-dimensional vector space. Captions with similar concepts occupy nearby coordinates.

FAISS Vector Search

Facebook AI Similarity Search (FAISS) is loaded at startup. When a user interacts with a video, we fetch its precomputed 384-d vector and run a K-Nearest Neighbors (KNN) search to retrieve similar videos, ranked by Cosine Similarity.

The Weighted Ranking Formula

The Rule-Based Scorer ranks candidate videos by summing seven distinct signal scores:

Signal Weight Methodology
Exploration 30% Uniform random float (adds dynamic variance on refresh).
Freshness 30% Exponential decay model with a half-life of 30 days.
Popularity 15% Log-scaled views + engagement rates. Boosts new clips to 0.8.
Category Interest 10% Matches user's category score normalized to a 0.0 - 1.0 range.
Creator Affinity 5% Prioritizes creators the user regularly likes or saves.
Similarity 5% Cosine similarity score generated by the FAISS vector search.
CF / Taste 5% Taste similarity overlap score from collaborative filtering.

4. Real-Time Feedback Loop

Every like, save, scroll, or loop triggers an immediate update to the interest vector database on the backend.

Delta Interaction Scoring

# Inside service.py
score_delta = new_score - prev_score
raw_scores[category] += score_delta

Liking a video adds `+3`. Unliking it sets like score to `0`, causing the subtraction `0 - 3 = -3`, which perfectly resets the score vector to its pre-liked state.

Baseline-Gravitating Decay

When swiping, categories that are inactive decay by a factor of `0.95`, gravitating toward a default neutral baseline score of `15.0`:

raw = 15.0 + 0.95 * (raw - 15.0)

The category of the active video is excluded from decay, ensuring interaction actions are net-positive.

5. Frontend Telemetry

The frontend interface visualizes the recommendation pipeline state in real time for absolute algorithmic transparency:

  • Active Persona Badge: Exposes the cold-start configuration (e.g. `Tech Enthusiast`) and details the user's base interests.
  • Interest Profile Vector Gauges: Displays real-time progress bars for category weights which update instantly on interaction clicks.
  • Floating Console Logs: Placed next to the Reels swiper. Autoscrolls internally by modifying `.scrollTop` directly, eliminating standard viewport jump scroll bugs.

6. Git Repository Branches

To maintain separate code states and baseline stability, the platform uses separate feature branches:

cleanest-code-working Preserved original baseline code, completely untouched.
delta-decay-fix Excludes target categories from the decay loop to prevent score drop.
interactive-session-scoring Implements the is_final parameter to isolate button clicks from loops.
ui-icon-upgrade Replaces heavy emojis in the swiper and sidebar with SVG icons.
ui-floating-logs Moves real-time logs to a side-by-side flex layout and fixes page jumps.
